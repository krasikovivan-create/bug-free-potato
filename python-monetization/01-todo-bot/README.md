# 📋 Telegram-бот «Список задач» (проект №1)

Бот, который хранит задачи пользователя, напоминает о них и выгружает всё в Excel.
Это первый портфолио-проект: его можно показать клиенту и продавать с доработками под его бизнес.

## Что умеет

| Команда | Что делает |
|---|---|
| любое сообщение или `/add текст` | сохраняет задачу |
| `/list` · `/list all` | открытые задачи (или все) — под каждой кнопки ✅ и 🗑 |
| `/done 3` · `/delete 3` | выполнить / удалить задачу №3 |
| `/remind 3 30m` | напомнить через 30 минут. Ещё: `2h`, `1d`, `1h30m`, `18:00`, `tomorrow 09:00`, `31.12 20:00`, `2026-12-31 20:00`; `/remind 3 off` — отменить |
| `/export` | присылает `.xlsx` со всеми задачами |
| `/tz Europe/Berlin` | часовой пояс пользователя (по умолчанию — `DEFAULT_TZ`) |

Напоминание приходит сообщением с кнопками **✅ Done / 💤 10 min / 💤 1 hour**.
Бот работает только в личных чатах; у каждого пользователя свои задачи и своя нумерация.

## Запуск за 5 минут

1. **Создай бота.** В Telegram открой [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя → скопируй токен.
2. **Установи зависимости** (нужен Python 3.10+):
   ```bash
   cd python-monetization/01-todo-bot
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```
3. **Впиши токен.** `cp .env.example .env` и вставь токен в `BOT_TOKEN=`. Файл `.env` в Git не попадает — токен это пароль от бота.
4. **Запусти:** `python bot.py` и напиши боту `/start`.

## Как устроен код

```
bot.py        команды, кнопки, фоновая проверка напоминаний (точка входа)
db.py         вся работа с SQLite — больше никто в базу не лезет
timeutil.py   разбор «30m» / «18:00» / «tomorrow 09:00» и вывод дат
exporter.py   сборка Excel-файла
texts.py      ВСЕ тексты бота — правишь только его, чтобы подогнать под клиента
tests/        автотесты (pytest)
```

Идея: Telegram присылает «обновления» → библиотека вызывает функцию-обработчик из `bot.py` → она читает/пишет
базу через `db.py` и отвечает пользователю. Раз в 30 секунд отдельная задача смотрит в базу, не пора ли
кому-то напомнить. Напоминания лежат в базе, поэтому переживают перезапуск бота.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Проверяют базу (изоляция пользователей, номера, напоминания), разбор времени (включая мусорный ввод,
часовые пояса, переход на следующий год) и экспорт.

## Безопасность — что уже учтено

- Токен только в `.env` (в Git не попадает); логирование `httpx` приглушено, потому что на уровне INFO оно печатает URL вместе с токеном.
- Текст задач экранируется перед отправкой в Telegram (HTML), а в Excel строка вида `=HYPERLINK(...)` записывается как текст, а не как формула.
- Пользователь видит и меняет только свои задачи — все запросы к базе фильтруются по `user_id`.
- Ввод вроде `/done 99999999999999999999` или `/tz ../etc` не роняет бота.

## Хостинг (важно)

**Бесплатного Heroku больше нет** (убрали в 2022-м), а у многих «бесплатных» тарифов диск временный:
после перезапуска файл `tasks.db` стирается, и все задачи клиента пропадают. Поэтому нужен хостинг с **постоянным диском**.
Актуальные цены и условия проверяй на сайтах сами — они меняются.

| Вариант | Комментарий |
|---|---|
| Дешёвый VPS (Hetzner, DigitalOcean и т.п.), порядка $4–6/мес | самый предсказуемый вариант; ниже — готовый systemd-сервис |
| Docker-хостинги с volume (Fly.io, Railway и т.п.) | собери из `Dockerfile`, подключи volume в `/data` |
| Домашний компьютер / Raspberry Pi | годится для демо и тестов |

### VPS + systemd

```bash
git clone <твой-репозиторий> && cd python-monetization/01-todo-bot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env        # впиши BOT_TOKEN
```

`/etc/systemd/system/todo-bot.service` (поправь пути и пользователя):

```ini
[Unit]
Description=Telegram todo bot
After=network-online.target

[Service]
WorkingDirectory=/home/bot/python-monetization/01-todo-bot
ExecStart=/home/bot/python-monetization/01-todo-bot/.venv/bin/python bot.py
Restart=always
User=bot

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now todo-bot
journalctl -u todo-bot -f                # логи
```

### Docker

```bash
docker build -t todo-bot .
docker run -d --restart=always --env-file .env -v todo-bot-data:/data todo-bot
```

## Что можно доработать под клиента (идеи для допродажи)

- Другой язык и тон — только `texts.py`.
- Доступ по списку разрешённых пользователей (бот для команды, а не для всех).
- Повторяющиеся напоминания, категории и приоритеты, дедлайны.
- Переезд с SQLite на PostgreSQL (меняется только `db.py`).
- Вебхуки вместо polling, админ-панель, статистика.

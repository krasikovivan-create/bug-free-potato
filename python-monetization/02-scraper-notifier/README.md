# 🔎 Парсер сайтов с уведомлениями в Telegram (проект №2)

Заходит на сайт по расписанию, находит новые объявления/товары/вакансии, отбирает подходящие под фильтры
и присылает их в Telegram. Под нового клиента почти ничего не пишется заново — меняется только `config.toml`
(адрес сайта, CSS-селекторы, фильтры). Это и есть то, что ты продаёшь.

## Что умеет

- Несколько сайтов в одном конфиге; несколько страниц на сайт (пагинация).
- Фильтры: слова в заголовке (`include` / `exclude`), диапазон цены.
- **Не спамит:** первый проход только запоминает то, что уже есть на сайте; уведомления — только о новом.
  Новое приходит пачками по 10 штук в одном сообщении.
- **Не теряет:** объявление считается отправленным только после того, как Telegram его принял.
  Не дошло — уйдёт при следующей проверке.
- **Говорит, когда сломалось:** сайт поменял вёрстку или лежит 3 проверки подряд — придёт предупреждение
  (один раз), а когда починится — сообщение «снова работает». Без этого скрейпер молча умирает, и клиент это замечает первым.
- **Вежливый:** читает `robots.txt`, делает паузы между запросами, повторяет при временных ошибках (429/5xx), не качает гигантские файлы.
- Сбой одного сайта не мешает остальным; кривой конфиг объясняется человеческим языком, а не traceback'ом.

## Запуск за 10 минут

Нужен Python **3.11+** (читаем TOML штатным `tomllib`).

```bash
cd python-monetization/02-scraper-notifier
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp config.example.toml config.toml                    # сайт и фильтры
cp .env.example .env                                  # токен бота и chat id
```

1. **Бот и токен.** В [@BotFather](https://t.me/BotFather): `/newbot` → скопируй токен в `.env` (`TELEGRAM_BOT_TOKEN=`).
2. **chat id.** Открой своего бота в Telegram, нажми Start, затем выполни `python scraper.py chat-id` — команда напечатает
   строку `TELEGRAM_CHAT_ID=...`, вставь её в `.env`.
3. **Проверь селекторы** (Telegram и база не трогаются): `python scraper.py check`
4. **Боевой запуск:** `python scraper.py once` (один проход) или `python scraper.py run` (по кругу каждые `interval_minutes`).

Первый `once`/`run` ничего не пришлёт — он запоминает текущие объявления. Новое придёт со следующей проверки.

## Как найти CSS-селекторы для сайта клиента

1. Открой страницу со списком в Chrome → правый клик по одному объявлению → **Inspect** (Просмотреть код).
2. Найди тег, который оборачивает **одно** объявление целиком (`<article class="product_pod">`, `<li class="result">` …) —
   это `item`. Селектор: `тег.класс`, например `article.product_pod`.
3. Внутри него найди заголовок (`title`), ссылку (`link`), цену (`price`) — селекторы пишутся **относительно** объявления.
4. Кнопка «Следующая» — `next_page`. Если само объявление — это ссылка `<a>`, используй `"."` («сам элемент»).
5. Запусти `python scraper.py check` и смотри, что нашлось. Правишь конфиг → снова `check`. Telegram при этом не трогается.

> Подсказка: в Inspect правый клик по элементу → Copy → Copy selector даёт готовый селектор — его надо упростить до коротких классов.

## Настройки (`config.toml`)

Общие (все необязательны, ставятся **выше** первого `[[sources]]`):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `interval_minutes` | 60 | период проверки в режиме `run` |
| `request_delay` | 2 | пауза (сек) между запросами к одному сайту |
| `timeout` | 20 | сколько ждать ответ сайта |
| `user_agent` | `ScraperNotifier/1.0` | как представляемся сайту; хорошо добавить контакт: `(+you@example.com)` |
| `respect_robots` | true | соблюдать `robots.txt` (false — только для своих сайтов) |
| `notify_on_first_run` | false | true — первым проходом прислать и всё, что уже есть |
| `db_path` | `scraper.db` | файл базы (перекрывается переменной `DB_PATH`) |

Источник (`[[sources]]`, по блоку на сайт):

| Ключ | Обязательный | Смысл |
|---|---|---|
| `name`, `url` | да | название в уведомлении и адрес страницы со списком |
| `item`, `title`, `link` | да | селекторы: объявление; заголовок и ссылка внутри него (`"."` = сам элемент) |
| `title_attr` / `link_attr` | нет | брать заголовок из атрибута (`title`), ссылку — из другого атрибута (по умолчанию `href`) |
| `price` | нет | селектор цены; понимает `£51.77`, `$1,299.00`, `1 500 000 ₽`, `12,50 €` |
| `next_page`, `max_pages` | нет | пагинация: селектор ссылки «дальше» и сколько страниц обходить (до 50) |
| `include` / `exclude` | нет | слова в заголовке: хотя бы одно из `include`, ни одного из `exclude` (регистр не важен) |
| `min_price` / `max_price` | нет | границы цены; если цену найти не удалось, объявление **не** пропускается |
| `allow_empty` | нет | true — «0 объявлений на странице» не считать сбоем (например, пустой поиск) |

## Устройство проекта

```
scraper.py    команды (check / once / run / chat-id) и логика одного прохода
config.py     чтение и проверка config.toml, понятные сообщения об ошибках
fetcher.py    скачивание страниц: robots.txt, паузы, повторы, лимит размера
listing.py    HTML -> объявления (CSS-селекторы, разбор цены, ссылки)
filters.py    подходит ли объявление под фильтры
storage.py    SQLite: что уже видели, прошёл ли первый проход, сколько сбоев подряд
notifier.py   отправка в Telegram (обычный HTTP, без библиотеки бота)
tests/        автотесты (pytest)
```

Один проход: `скачать → разобрать → отфильтровать → выкинуть уже виденное → отправить → запомнить`.

## Что можно парсить, а что — нет (важно для заказов)

- **Сначала ищи официальный способ**: у многих сайтов есть API, RSS или выгрузка — это надёжнее и законнее, чем HTML.
- **Читай условия сайта и `robots.txt`.** Крупные площадки объявлений (в том числе Avito) запрещают автоматический сбор
  в пользовательском соглашении и активно защищаются капчей и блокировками. Не обещай клиенту «спарсить Avito»:
  это нарушение правил площадки, и оно ещё и быстро ломается. Честные заказы — сайты самого клиента, открытые каталоги,
  вакансии/новости с разрешённым доступом, партнёрские выгрузки.
- **Не собирай персональные данные** (телефоны, почты, профили людей) без законного основания — это отдельная юридическая тема.
- Не отключай `respect_robots` на чужих сайтах и не ставь `request_delay` в ноль.

Для тренировки подходят сайты, созданные для парсинга: `books.toscrape.com`, `quotes.toscrape.com`
(именно на нём построен `config.example.toml`).

## Как запускать на сервере

База (`scraper.db`) обязана лежать на **постоянном диске**: потеряешь её — бот забудет, что присылал, и отправит всё заново.

**Вариант 1 — cron (проще всего).** Раз в час, без постоянно работающего процесса:

```cron
0 * * * *  cd /home/bot/python-monetization/02-scraper-notifier && .venv/bin/python scraper.py once >> scraper.log 2>&1
```

**Вариант 2 — systemd** (`/etc/systemd/system/scraper.service`): процесс работает постоянно, сам перезапускается.

```ini
[Unit]
Description=Site scraper with Telegram notifications
After=network-online.target

[Service]
WorkingDirectory=/home/bot/python-monetization/02-scraper-notifier
ExecStart=/home/bot/python-monetization/02-scraper-notifier/.venv/bin/python scraper.py run
Restart=always
User=bot

[Install]
WantedBy=multi-user.target
```

**Вариант 3 — Docker:**

```bash
docker build -t scraper .
docker run -d --restart=always --env-file .env \
  -v scraper-data:/data -v "$(pwd)/config.toml:/app/config.toml:ro" scraper
```

Бесплатного Heroku больше нет, а на хостингах с временным диском без volume база стирается при перезапуске — выбирай VPS (порядка $4–6/мес) или Docker-хостинг с постоянным томом.

## Идеи для допродажи клиенту

- Фильтр по описанию объявления, а не только по заголовку; несколько чатов или каналов получателей.
- Источники в формате JSON/RSS (многие сайты отдают данные без HTML).
- Сайты, где список подгружается JavaScript'ом (понадобится Playwright или прямой вызов их внутреннего API).
- Выгрузка истории найденного в Excel (по аналогии с проектом №1), команды управления фильтрами прямо из Telegram.
- Переезд с SQLite на PostgreSQL, ежедневная сводка.
